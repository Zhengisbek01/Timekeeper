# Timekeeper — учёт рабочего времени по QR

Группа компаний: **KazMining, MKA engineering, KazAgroFeed**.

- Планшет у входа работает под **отдельной учётной записью киоска** и показывает QR-код, который меняется каждые 30 с.
- Работник **регистрируется сам**: ФИО, компания, должность, телефон, email, пароль. Входит по **email и паролю**.
- **HR подтверждает** каждую заявку — до этого отметиться нельзя.
- Дни с отметками попадают в табель **автоматически**. Отпуск, БС, больничный, командировку и т.д. HR ставит вручную.
- **Опоздания — красным**: на экране «Сегодня», в табеле, в кабинете работника, на планшете и в Excel.
- Раздел **«Отчёты»**: табель, опоздания, отсутствия, сводка по компаниям, журнал отметок, список работников — в Excel, по месяцу и компании.

Стек: React + Vite, Supabase (PostgreSQL + Auth), Vercel.

## Запуск

**1. Supabase**
1. Создайте проект на supabase.com.
2. SQL Editor → вставьте `supabase/schema.sql` → Run. Создадутся таблицы, три компании и календарь 2026.
3. Authentication → Sign In / Providers → Email → **выключите «Confirm email»**. Доступ работнику всё равно открывает HR, а учётные записи киосков используют служебные адреса, на которые письма не доходят.
4. Authentication → URL Configuration → Site URL — адрес сайта на Vercel.
5. Project Settings → API — скопируйте `Project URL` и `anon public` key.

**2. Локально**
```bash
cp .env.example .env   # URL, ключ, название, домен служебных адресов
npm install
npm run dev
```

**3. Vercel** — импортируйте репозиторий, добавьте переменные из `.env.example`, Deploy.

**4. Первый HR**
Зарегистрируйтесь в приложении как работник, затем в SQL Editor:
```sql
update public.employees set role = 'admin', status = 'approved', approved_at = now()
 where email = 'hr@company.kz';
```
Следующих HR назначает уже существующий HR: «Работники» → карточка → Роль «HR».

**5. Планшет**
HR: «Киоски» → название + логин (например `kiosk-main`) → система покажет одноразовый код.
Планшет: откройте `/kiosk` → «Активация» → логин, код, придумайте пароль. Планшет остаётся в системе; экран не гаснет. Если планшет потерян — «Сбросить» в разделе «Киоски»: старая сессия перестанет работать, выдаётся новый код.

**6. Работники**
Раздайте ссылку `https://<ваш-домен>/login?mode=up` (или QR на неё). Новые заявки появляются во вкладке **«Заявки»** с красным счётчиком. HR проверяет данные, указывает график и подтверждает.

## Для работника
- **Код быстрого входа.** После первого входа по email и паролю каждый придумывает свой код из 4 цифр. Дальше приложение открывается по коду. Код хранится только на этом телефоне; после 5 неверных попыток нужно войти по паролю и задать новый код. «Забыли код?» → вход по паролю.
- **Отметка.** Обычная камера телефона → навести на QR на планшете → нажать на ссылку → ввести код. Или в приложении кнопка **«Отметиться — сканировать QR»**.
- **Дата начала учёта.** Дни до неё не считаются неявками. Проставляется автоматически при регистрации, HR может изменить.

## Для HR — вкладка «Сегодня»
Статус каждого (на месте / ушёл / опоздал / ранний уход / не отмечался / отсутствует), первый приход и последний уход, **все отметки за день** (→ приход, ← уход, ✎ ручная), сколько отработано (у тех, кто на месте, — до текущей минуты), **журнал всех отметок** по времени и выгрузка дня в Excel.

На планшете фамилии не показываются — только QR, часы и короткая инструкция. Подтверждение отметки работник видит у себя на телефоне.

## Роли

| Учётная запись | Вход | Что видит |
|---|---|---|
| Работник | email + пароль | Свои отметки, часы, опоздания. До подтверждения — экран «Заявка на рассмотрении» |
| HR | email + пароль | Сегодня, Табель, Заявки, Работники, Отчёты, Киоски, Календарь |
| Киоск | логин + пароль | Только экран QR и ленту последних отметок |

## Как считается табель (`src/lib/timesheet.js`)
- Интервал «приход → уход» относится к дню прихода (ночные смены поддерживаются).
- Одна непрерывная сессия дольше 5 ч → вычитается перерыв из карточки (ст. 81 ТК РК).
- **Опоздание** — первый приход позже начала смены более чем на 5 мин. В дни отсутствия опоздание не считается.
- Код дня: отсутствие от HR → его код; есть отметки → «Я» (или «РВ» в выходной); выходной → «В»; прошедший рабочий день без отметок → «НН».
- Коды отсутствий: ОТ, БС, У, ОЖ, Б, К, Г, ПК, ПР — список правится в `CODES`.

## Безопасность
- QR-токен = HMAC(киоск + 30-секундное окно, секрет киоска); принимается ~2 минуты. Фото QR быстро устаревает.
- Отметку проверяет серверная функция `check_in`: только вошедший, **подтверждённый HR** и не уволенный работник.
- Токен выдаётся только учётной записи киоска (`kiosk_token`), секрет на планшет не попадает.
- RLS: работник видит только свои данные; таблицы киосков и чужие отметки доступны только HR.

## Персональные данные
При регистрации работник даёт согласие на обработку ПД. Для промышленной эксплуатации Закон РК «О персональных данных и их защите» требует хранить базу на территории РК — используйте self-hosted Supabase на казахстанском сервере.
